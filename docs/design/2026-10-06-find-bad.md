# DeepLabeling — slice 4: Find Bad

**Status:** approved 2026-10-06 · plans 4a (the core) and 4b (the full frame) implemented; 4c (the grid) next
**Scope:** slice 4 of [the app foundation](2026-10-04-app-foundation.md#slices): a queue whose
items are the labels the model disagrees with, each focused on its label line; crop tiles in
the grid; the finding spotlighted in the full frame; one-key fixes; and dismissals that
persist. It replaces the legacy app for cleaning with the model. Everything slices 1–3 built
stays as it is, except where this spec says so.

## Why

Cleaning is the last of the [daily workflows](2026-10-04-app-foundation.md#why) the legacy
app served: run the model over a dataset, then walk the labels it disagrees with — a box of
the wrong class, a box around nothing, a box the model barely recognises — and fix or
dismiss each. The legacy app did it in a separate crop-review window with its own
navigation, flipped verdicts between runs, compared raw model ids with dataset ids, forgot
its dismissals on restart, and lost its Start button on short screens
([legacy-defects.md](../knowledge/legacy-defects.md)). Each of those is a rule below.

## Decisions

| Question | Decision |
|---|---|
| How findings are served | **A second queue source, `Findings`**, beside `ImageFilter`, in the one queue system: paging, the grid, review marks, undo and rebuilds are slice 1–3's. A separate review window and findings precomputed by the dataset pass were the alternatives |
| What a scan covers | **The images a filter selects**: the same splits and conditions as an image queue; with none, the whole dataset |
| One-key actions | **Take the model's class, take the model's box, dismiss**, beside the editor's own keys; after any of them the cursor moves to the next finding |
| Several findings at once | **Selected crop tiles in the grid** take an action together, as one edit |
| What a dismissal is tied to | **The label as it is, and the finding kind**, from any model: editing the label voids it; a new model does not resurface it |
| The full frame | **Dim around the finding and keep the zoom**: paging findings never moves the view |
| Class groups | **From the yaml's `groups:` block**, as the legacy app adopted them; no editor in this slice |

## Findings

The rules are [matching.md](../knowledge/matching.md)'s; this section says how DeepLabeling
applies them. Predictions come from the loaded model's rows in the
[prediction store](2026-10-05-model-assist.md#the-prediction-store), translated through its
[class map](2026-10-05-model-assist.md#the-class-map).

### Settings

Saved per root, and edited in the queue editor:

| Setting | Default | Meaning |
|---|---|---|
| confidence floor | 0.40 | what the model sees; never below the store's floor ([one floor](../knowledge/matching.md#one-floor-and-per-kind-ceilings)) |
| matching IoU | 0.5 | a candidate overlaps the label at least this much |
| wrong class | on, ceiling 1.0 | reported when the deciding prediction's confidence ≤ the ceiling |
| not an object | on, band 0 to the matching IoU | reported when the nearest prediction's IoU is inside the band |
| weakly seen | off, cutoff 0.60 | reported when the deciding prediction agrees below the cutoff |

### Judging one image

- **Candidates** of a label are the predictions at or above the floor, of any class, mapped
  or not, overlapping it at IoU ≥ the matching IoU. The **deciding** prediction is the most
  confident candidate, ties to the better overlap
  ([why](../knowledge/matching.md#candidates-and-the-deciding-prediction)).
- **Wrong class:** the deciding prediction is mapped and does not agree with the label, at
  or below the ceiling. Its score is the deciding confidence.
- **Not an object:** the label has no candidate, its class is checkable, and the nearest
  prediction's IoU is inside the band. Its score is 1 − that IoU. The nearest box is kept
  only at IoU ≥ 0.10 (`legacy/yolo_labeling/core/badscan.py::NEAREST_MIN_IOU`).
- **Weakly seen:** the deciding prediction agrees, below the cutoff. Its score is 1 − the
  deciding confidence.
- **An unmapped deciding prediction is inconclusive**: no finding, and no weaker mapped
  candidate overrules it ([why](../knowledge/matching.md#unmapped-classes-are-inconclusive)).
- A kind's findings never depend on which other kinds are on.

### Class groups

- **Agreeing** is the same dataset class or the same group
  ([prediction maps and class groups](../knowledge/datasets.md#prediction-maps-and-class-groups)).
- **Checkable** is a class some model class maps to, directly or into its group
  ([the checkable-class guard](../knowledge/matching.md#the-checkable-class-guard)).
- Groups name classes by name. A name the yaml lacks is ignored; a yaml without `groups:`
  has every class in a group of its own.

### What a finding holds

The image; the label line, by reference and by its text; the kind and its score; the
model's box and class when there is one (the deciding prediction, or the nearest); and its
**crop**: the union of the label and the model's box, the model's reach capped at 2× the
label's larger side, padded by a quarter of that side and at least 4 px, inside the frame
([the review crop](../knowledge/matching.md#the-nearest-box-and-the-review-crop),
`legacy/yolo_labeling/core/crops.py::render_review_crop`).

### Dismissals

- **A dismissal is `(image, label line text, kind)`**, stored per dataset in its state
  folder as `dismissals.json`, written atomically and debounced like the
  [review marks](2026-10-04-app-foundation.md#review-marks).
- A scan leaves dismissed findings out. Editing the label changes its text, so its
  dismissals no longer match.
- Dismissing is not an edit: undo leaves it alone, and `D` on a dismissed finding takes it
  back.

## The queue

- **The `Findings` source** holds the scope (splits and conditions, as `ImageFilter`) and the
  settings above, saved with the queue for each opening.
- **The scan runs on the build worker**: for each image the scope selects, its labels and the
  model's rows, judged. Findings are ordered by kind — wrong class, not an object, weakly
  seen — then by score, strongest first, so items arrive when the scan completes. The core
  queue keeps items by a sort key of their own; image queues keep dataset order.
- **While it scans**, the queue chip says `scanning 12,000 / 45,252`; at the end it counts
  each kind and what could not be settled: `412 wrong class · 1,733 not an object · 9,881
  not inferred`.
- **An item's key** is its image, its line and its kind; its focus is the label line.
- **Kept current**, as slice 3's model queues: an edit re-judges the image, and a finding
  that no longer holds shows *fixed*; a dismissal shows *dismissed*; neither leaves the
  queue until it is rebuilt. A model or class-map change rebuilds it; without a model it
  waits and says so; images never inferred are counted, *Infer this queue* infers them, and
  their findings join in their place as predictions arrive.

## Window

### The list and the chip

- A row reads `camA/0001.jpg — wrong class: car → truck 0.82`,
  `… — not an object: bus_m (nearest 0.03)`, or `… — weakly seen: car 0.41`; a fixed or
  dismissed finding says so.
- The inspector gains a *Finding* line: the kind, the score, the model's class and
  confidence.

### The full frame

- **The spotlight:** everything outside the finding's crop is dimmed; the model's box is
  drawn dashed beside the label, captioned with its class and confidence; the label arrives
  selected. The view keeps its zoom.

### Keys

| Key | In a Findings queue |
|---|---|
| `M` | take the model's class (wrong class, weakly seen) |
| `B` | take the model's box, keeping the label's class (when the finding has one) |
| `D` | dismiss, or take the dismissal back |
| `Delete`, class keys | as everywhere |

After a fix or a dismissal of the current finding, the cursor moves to the next finding.
A fix in the full frame marks the image reviewed, as any edit does.

### The grid

- **A tile is the finding's crop**, decoded at tile size: the reader clips and scales as it
  decodes, honouring EXIF orientation. The label is drawn in its class colour and the
  model's box dashed; the caption names both and the score. Tiles are cached like
  thumbnails.
- **Ctrl- or Shift-click selects several tiles.** `M`, `B`, `D`, `Delete` and the class keys
  then apply to every selected finding as **one** edit, undone as one; dismissals are
  recorded together. A grid action marks nothing reviewed: a crop is not the image.

### The queue editor

*Source: Images / Findings.* Findings adds the settings, refused by name as slice 3's rows
are; its floor starts at 0.40.

## Errors

| Situation | What happens | Where it shows |
|---|---|---|
| A Findings queue with no model | the queue is empty; it says it needs a model | notice, queue chip |
| Images never inferred | left out; counted | queue chip |
| `B` on a finding without a model box | nothing changes | status bar |
| `M` on a not-an-object finding | nothing changes | status bar |
| A grid action meets a read-only label file | that finding is skipped; the rest are one edit; the skipped are counted | status bar |
| A crop cannot be decoded | the tile says so | tile |
| `dismissals.json` cannot be read | set aside and started again | notice |

## Performance targets

Measured on `data_13class.yaml`, on this machine. A missed target is recorded with its
measured value, not quietly dropped.

| Action | Target |
|---|---|
| a Findings scan over 45k images, complete: cold / warm | ≤ 30 s / ≤ 5 s |
| the window while it scans | the event loop never waits more than 100 ms |
| a page of crop tiles | ≤ 1 s |
| the next finding, prefetched | ≤ 100 ms, as paging images |

## Testing

- **Core, on the generated edge-case dataset:** each kind, through class groups; an unmapped
  deciding prediction, inconclusive; checkable through a group; deciding by confidence, not
  overlap; a ceiling never removing a prediction from matching; the not-an-object band and
  the 0.10 nearest minimum; the crop's reach cap (a 400×40 prediction over a 40×40 label);
  the sort order; dismissals kept while the line is unchanged, void after an edit, and
  persisted; a queue ordered by its own key.
- **UI:** list rows and badges; crop tiles read back from their pixels; a multi-tile action
  as one edit, undone whole; the spotlight's dimming read from pixels; `M`, `B`, `D` and
  moving on; waiting for the model and rebuilding; dismissals across a relaunch.
- **One measurement script**, read-only, for the [targets](#performance-targets).

## Out of scope

- Editing class groups.
- The confusion-pair query ("every A the model calls B") of the legacy scan.
- Exporting crops: slice 5's.
